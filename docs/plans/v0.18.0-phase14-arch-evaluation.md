# Phase 14 Architecture Evaluation: Native Android vs Progressive Web App (PWA) vs Hybrid

**Date:** 2026-08-22  
**Target Platform:** Google Pixel 7 Pro (Android 14/15/16, 1440x3120 LTPO 120Hz, Tensor G2)  
**Related Issue:** #167 (`SPIKE(phase14-arch)`)  
**Milestone:** Milestone 20 (`v0.18.x - Phase 14: Mobile PWA & Android Companion`)

---

## 1. Executive Summary & Recommendation

For **AI Brain Phase 14**, our core goal is to deliver a **mobile companion experience** focused on:
1. **Library & Search**: Fast touch navigation, quality badges, offline indicators.
2. **Reading Studio**: Distraction-free long-form reading, media and YouTube synchronized transcript navigation.
3. **Notes & AI Consumption**: AI digest reading, rich manual note authoring, and offline IndexedDB resilience.
4. **AI Companion (Ask)**: In-item conversational Q&A with token streaming and citation drawer previews.
5. **Quick Capture**: 1-tap capture bottom sheet and system share target integration.

We evaluated three potential technical approaches:
1. **Native Android App (Kotlin + Jetpack Compose + Room + Retrofit)**
2. **Progressive Web App (PWA with Web Share Target, CacheStorage, and IndexedDB)**
3. **Hybrid Wrapper (Capacitor 8 / Trusted Web Activity - TWA)**

### Decision: Progressive Web App (PWA)
**Verdict**: We select the **Progressive Web App (PWA)** architecture as the primary foundation. An enhanced PWA provides:
- **100% Code Reuse**: Zero duplication of Markdown parsers, SSE stream handlers, design tokens, or database contracts.
- **Native Android Share Target Integration**: Android Chrome registers PWAs into the system share sheet via `share_target` in `manifest.webmanifest`.
- **Instant Deployment**: Changes deployed to `brain.arunp.in` update immediately on the Pixel 7 Pro without compiling APKs, signing keystores, or sideloading via `adb`.
- **Fluid 120Hz Rendering**: Leveraging CSS `100dvh`, View Transitions API, and touch-optimized components.
- **Offline Durability**: Combining Service Worker CacheStorage for reading pages with IndexedDB (`brain-manual-notes-v2`) for local note drafts.

## 2. Comparative Analysis Across Architectural Axes

| Evaluation Axis | Native Android (Compose) | PWA (Chrome on Android) | Hybrid (Capacitor/TWA) |
|---|---|---|---|
| **Single Codebase & Velocity** | ❌ High duplication (separate Kotlin UI, models, network stack) | ✅ **100% unified** (TypeScript, Next.js, React 19, Tailwind) | ⚠️ Mixed (Web code + native Gradle wrapper) |
| **System Share Sheet** | ✅ `ACTION_SEND` Intent Filter | ✅ **Web Share Target API** (Manifest v2) | ✅ `@capgo/capacitor-share-target` |
| **Offline Reading Mode** | ✅ Room SQLite | ✅ **Service Worker Cache + IndexedDB** | ✅ Service Worker + Capacitor filesystem |
| **120Hz Touch Fluidity** | ✅ Native Compose | ✅ **Chrome Blink on Pixel 7 Pro (120Hz)** | ⚠️ WebView overhead |
| **AI Stream & Markdown** | ❌ Needs custom SSE parser & Compose Markdown | ✅ **Native `fetch()` stream & `react-markdown`** | ✅ Web implementation |
| **Deployment & Updates** | ❌ Complex APK build & sideloading | ✅ **Instant live deployment on server** | ⚠️ App rebuild needed for native changes |

## 3. Pixel 7 Pro Specific Optimizations

1. **Dynamic Viewports (`100dvh`, `100svh`)**:
   - Android Chrome dynamically expands and collapses its top URL bar and bottom navigation controls during scroll.
   - Using CSS dynamic viewport units (`min-h-[100dvh]`) prevents abrupt layout jumps when virtual keyboards or browser bars toggle.
2. **Safe Area Insets**:
   - `env(safe-area-inset-top)` and `env(safe-area-inset-bottom)` protect floating bottom bars and FAB buttons from Android navigation pills.
3. **Web Share Target API (`manifest.webmanifest`)**:
   - Directly maps shared URLs and text snippets from YouTube, Chrome, Twitter/X, and Reddit into the `/capture` endpoint.
4. **Haptic Feedback**:
   - Subtle tactile confirmations via `navigator.vibrate?.(10)` on action button taps, note saves, and tab switches.
