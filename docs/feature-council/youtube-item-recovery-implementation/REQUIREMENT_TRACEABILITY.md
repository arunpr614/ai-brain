**Status rule:** `Verified` requires named implementation and executed test evidence. `Partially verified` records an executed Stage 1 control while later schema, feature, packaged, or live evidence in the same requirement remains open; all other rows remain `Planned`.
**Path rule:** `current:` means the path existed on the frozen baseline and is an affected caller, writer, or compatibility surface. `proposed:` records the Stage 0 path allocation and does not by itself assert whether that allocation later landed; the implementation-evidence and status cells are authoritative for later stages.
**Release rule:** browser-visible transcript capture and held-transcript processing remain denied in production. Synthetic, packaged, migration, and isolated-lab evidence cannot authorize production enablement. Production-safe link-only remains a separate conditional release and requires migration 027 plus its zero-fetch and zero-recovery evidence.

## Evidence update protocol

For each implementation wave, change a row from `Planned` only after recording:

1. the exact landed code path and contract version;
2. the exact landed test path and named cases;
3. the executed command, timestamp, pass/fail counts, and durable artifact path;
4. the independent review disposition;
5. the permitted release environment and residual risk.

Proposed paths must be relabeled `current` only after they exist on the reviewed implementation baseline. A passing synthetic, packaged, migration, or isolated-lab row does not authorize browser-visible transcript capture or held-transcript processing in production.
