## D-008 narrow handoff contract

The corrected candidate contract is defined in [`decisions/TWO_CHANNEL_TRANSFER_ADDENDUM.md`](decisions/TWO_CHANNEL_TRANSFER_ADDENDUM.md). The focused Stage 0 recheck accepted it at the contract level and found no remaining P0/P1 defect. Any implementation that sends transcript text through runtime messaging, stores it in the worker, lets the page select the destination, exposes the paired bearer to the panel/page, accepts a foreign extension/web origin, or leaks the one-time grant violates this decision. Chrome implementation remains blocked on migration 027, package/security evidence, and the separate live-lab gates.

## Decision review triggers

A new reviewed decision is required before:

- enabling browser capture or held-transcript processing in production;
- adding persistent YouTube host access or a static YouTube content script;
- using MAIN-world execution, player responses, caption URLs, cookies, or account data;
- changing intent, extractor, normalization, consent-copy, provider-plan, or processing-manifest versions;
- relying on a Chrome API above the frozen minimum version;
- contracting the expanded schema or permitting previous-binary rollback;
- conducting a live canary or retaining live transcript content.
